# 墨場：可計數因子評分卡研究與設計草案

更新日期：2026-10-28（台北）。本文保留原研究設計與證據範圍；後續簡化整數評分卡已完成實作、實測及實驗部署，結果與限制見 [實測上線紀錄](./FACTOR_SCORECARD_RELEASE.md)。未證明穩定優勢，未改動既有 Elo、APEX 或融合權重。

## 結論與研究範圍

可以把賽前條件轉成 −2、−1、0、+1、+2 的整數評分。學術上對應 sparse integer scoring systems；重點是由訓練資料選規則、權重與校準，而非憑印象把有利消息一直加上去。評分單位不是籃球比分，也不是固定的勝率百分點。

本輪以六組問題檢索到 40 筆候選論文摘要，另查核更正與反證。選讀下列 13 篇研究的方法／結果段落（包括 JMLR 論文前 12 頁），另查閱一份短篇更正；另兩篇研究僅採摘要。這不是窮盡文獻的系統性回顧，也沒有逐頁讀完所有候選全文。摘要篩選清單保存在 [factor-literature-screening.json](./factor-literature-screening.json)。未將預印本、同篇不同版本、摘要與原始全文當成多份獨立證據。

## 一個架構，分開三種目標

可以共用資料庫與因子版本，但勝負、過盤、大小分須各自擬合或校準：

- 勝負分數：正值支持主隊，負值支持客隊；必須在 Elo 已知實力與主場優勢之外檢驗增量價值。
- 讓分分數：正值支持主隊過盤，負值支持客隊過盤；必須包含該時點的讓分線。主隊勝率高不表示能過深盤。
- 大小分分數：正值支持大分，負值支持小分；圍繞節奏、得分效率與總分線，不能沿用勝負分數。

整數分與機率分開。可測試 `logit(p_new) = a + b * logit(p_base) + gamma * S` 的保守校準形式；其中參數只能在訓練／校準期間估計。若因子已包含在基準模型中，須做消融與重複資訊檢查。尚無證據時 gamma 維持 0，不能設定「每 +1 分等於勝率 +5%」。同一總分也應顯示因子組成與缺漏，而非隱藏不同風險。

## 候選規則草案：以下分數只是待驗證示例

| 組別 | 已知賽前條件（以主隊為方向） | 示意分數 | 第一版限制 |
| --- | --- | --- | --- |
| 賽程與疲勞 | 主隊較充分休息、客隊背靠背；對稱情況反號 | +1 / −1 | 使用兩次開賽間隔的代理值，不稱為實際睡眠或休息時數；門檻只在訓練期選。 |
| 同組的嚴重疲勞 | 客隊背靠背兼長距離移動，主隊休息充分；對稱情況反號 | +2 / −2 | 替代前一條，不能再把 +1 疊加；全組上限 ±2。旅行方向暫不給固定分。 |
| 陣容可用性 | 官方確認缺陣造成的預期輪替／能力損失，主隊少於客隊 | +1 或 +2；相反則負值 | 要有賽前公告、比賽配對、過往分鐘與收縮後能力；不能用「明星」名氣硬定兩分。未知先發不當健康。 |
| 投籃對位 | 過去場次、對手調整後的 eFG% 對位差 | −2 至 +2 | 一般與明顯差距互斥，不得把同一投籃表現再以得分、命中率、連勝各加一次。 |
| 球權與籃板 | 失誤壓力、進攻籃板對位 | 各 −1 / 0 / +1 | 技術組總量限幅，先做逐項消融；不直接照搬 Oliver 經驗百分比。 |
| 節奏 | 預期回合數高於／低於當時基準 | 大小分 +1 / −1 | 不替勝負加分；僅用賽前已完賽資料。 |
| 攻守效率與線差 | 收縮後的總分估計相對當時總分線 | 大小分 −2 至 +2 | 若 APEX 基準已有這些訊息，應測試殘差貢獻，不能雙重計算同一估計。 |
| 未確認或資料過期 | 尚未公告、擷取晚於預測時點、歷史資料不可得 | null／不評分 | 不能標成「確定 +0」；另列缺漏並降低可用程度，必要時停止發布。 |

`0` 只代表資料有效且規則未觸發。`null` 是不知道，兩者在資料層必須分開。

示例：休息優勢 +1、對手已確認輪替損失 +2、自隊籃板對位 −1，已知合計 +2。這不是預測多贏兩分，也不是 60% 勝率；如果還有關鍵先發未知，顯示「已知 +2，資料不完整」，不輸出校準勝率。

## 計數與記憶方式

每場從 0 重新評估，不把整季發生過的好事永久累加。同一條件每場只算一次，賽前公告更新時產生新快照並保留舊版。以 `(event_id, target, factor_version, input_hash, cutoff_at)` 識別結果；同資料重跑讀快取，避免把重複爬取當成新事件。

近期狀態若要延續，應在底層用具時效的滾動統計／指數衰減；球員缺陣只影響其適用的比賽，恢復後不繼續扣分。每個貢獻保存規則 ID、原始觀測、公告與觀測時間、來源、適用賽事、分數及缺漏原因。凍結後的新消息不得覆寫原賽前版。

## 驗證與採用門檻

1. 固定可用資訊截止點，例如開賽前 60 分鐘。當場實際投籃、實際上場分鐘、賽後名單、季末排名、未來收盤價一律不能作為該時點輸入。
2. 依賽季、日期做外層時序測試；分箱、缺值策略、權重及校準都在較早的內層訓練期決定。同場主客兩列須進同一折，不可用隨機逐列切分製造資料穿越。
3. 先比較 Elo、APEX、融合原版，再比較各自加評分卡；如果只有總分命中率較高，卻讓 Brier／Log Loss、校準或比分誤差惡化，不稱為升級。
4. 讓分與大小分需真實賽前盤口及擷取時間。走盤保留為第三種結果，或清楚使用排除走盤的條件機率；不能把「不是主隊過盤」全當客隊過盤。獲利檢驗還需同時點、實際可取得的價格及成本，方向命中本身不是報酬率。
5. 按比賽日／賽季做相依性合適的區塊重抽樣、逐季穩定性與敏感度檢查，記錄所有嘗試的因子與門檻，保留最後未碰過的測試區間，避免只報最佳組合。
6. 有時序資料的賽程／比分特徵可先做歷史訓練；沒有當時傷停公告與陣容資料的日期不能倒填，陣容因子先向前收集。其後凍結規則做真實賽前觀察，再由人工決定是否採用。

2026-10-27 22:20 台北的私人彙總是 45 場 Elo 封存、9 場連結結果；APEX 有效配對 0，增量模型已學 9 場。這與另一份公開 10/24–10/25 歷史核對 19 場是不同範圍，不能相加當成同一樣本。既有 100 場候補門檻只是工程保護條件，不是任何新因子有效的統計證明。評分卡通常需要跨季、數千場可追溯歷史資料與足夠前瞻結果，精確需求須依模型複雜度與估計誤差決定。

## 低成本實作定位

可用 CPU 進行規則評分與小型整數模型搜尋，手機只負責查看雲端結果。數值管線不需要逐場呼叫付費語言模型，也不要求 GPU；實際訓練時間取決於資料與搜尋限制，不保證零託管費用。優先使用現有資料與快取，不另開高頻爬蟲。

[FasterRisk 官方專案](https://github.com/interpretml/FasterRisk)提供 BSD-3-Clause 開源實作，可作後續候選；本輪沒有安裝新依賴或替換主模型。論文的方法授權不等於 NBA 資料的商業再散布授權。

本文保留原研究時點的設計與限制。後續原整數模型已完成實測並以實驗狀態上線；新增陣容與技術對位則已接入觀測、保存及前瞻封存，但預測權重仍為零。分別見 [原整數模型實測](./FACTOR_SCORECARD_RELEASE.md) 與 [陣容觀測上線](./LINEUP_CONTEXT_RELEASE.md)，不可把原模型成績當作新陣容效果。
