## 觀測的內容

| 條件 | 實際構造 | 缺漏處理 |
|---|---|---|
| 已報缺陣角色 | 最近最多5場有效球隊樣本，對球員最近3次實際出賽取平均分鐘；至少2次才可匹配角色 | 新人、長期缺陣、缺少紀錄保留未知；角色分鐘合計不等於能力損失或實際將缺少的分鐘 |
| 上場負荷 | 近期平均角色分鐘最高的5位常用輪替，截至生成時點近72小時的實際出賽分鐘 | 缺完整輪替或不足3場球隊樣本留未知；不是對未來賽程的實際分鐘預言 |
| 可觀測輪替覆蓋 | 近況至少2次出賽且角色分鐘至少10的球員，分列已報Out、存疑與未列於上述兩類 | 未報缺陣不等於已確認健康、先發或可出賽；不宣稱替補能力已估得 |
| 技術對位 | 過去比賽自身投籃效率／失誤／進攻籃板，與對手曾允許的對應數據組合 | 只比較均值，尚非對手強度調整、護框追蹤或逐回合球風模型；不足3場留未知 |
| 節奏 | 兩隊過往近似回合數；有完整節數才能按48分鐘校正延長賽 | FGA−OREB+TO+0.44FTA 的近似值，不是官方pace；聯盟基準至少20隊可估才分級 |
| 三分依賴 | 兩隊過往三分出手占比 | 只標記結果不確定性，不直接代表大分或勝負優勢 |

觀測級別的門檻是待驗證規格：已報角色差30／60分鐘、前五角色負荷差100／200分鐘、投籃效率差2／4百分點、失誤差2／4百分點、進攻籃板差3／6百分點、回合差2／4；雙方三分占比皆至少40%列為依賴標記。這些都**沒有學得權重，沒有加到勝率或比分**，不能冒稱有效加減分。

替補能力、球員能力損失、官方先發、護框／投籃位置追蹤與實際旅行路線仍未知。ESPN Out 只代表該公開來源回傳缺陣狀態，不冒稱 NBA 官方已確認。不得將本輪日期的傷停公告倒填到舊賽事來訓練。

## 時序、記憶與來源保護

- 每場觀測只用較早台北比賽日的已完賽資料，且必須在生成前已實際擷取；舊日期的函式呼叫也不接受在其開賽後才取得的 box score。
- 傷停快照必須在生成前、開賽前擷取，6小時內有效；距開賽超過48小時保留未知。每個球員的紀錄時間也須能核對，晚於快照者排除。
- 同球員同隊報告去重；相同紀錄時間出現相反狀態則轉成未知。已有明確但互相衝突的球員ID時，拒絕用同名補配。
- 完整輪替至少5位有實際分鐘，球隊分鐘合計與比賽長度乘5的差不得超過8分鐘，避免部分 box score 當完整名單。
- 每場及每個觀測版本只保存第一次前瞻紀錄，不覆寫。完賽後核對event、主客隊、開賽時間與至少60分鐘前封存條件，附上分差和總分標籤；這些是特徵研究標籤，不是新模型命中率。
- 成功保存的近期完賽細節不再為回補而重抓；公開主收集器新增24小時的完賽細節快取，會核對同一賽事、主客隊、比分及原始擷取時間，過期或比分更正時重新取得。
- 回補每次最多12場，只處理現有公開賽程中的近期缺漏；失敗6小時內不重試。同份傷停內容按hash去重，保留初次及最近觀測時間。必要的特徵重算仍會執行，不等於完全不讀舊資料。
- 沿用原本每小時更新排程；不需要GPU、不逐筆呼叫語言模型，仍受既有託管額度與來源使用條款限制。

## 檔案與介面

- `scripts/context_factors.py`：有界回補、球員角色、技術觀測、傷停去重、封存與結算。
- `data/context-history.json`：可追溯的已完賽球員與技術細節。
- `data/context-injury-history.json`：不同傷停內容的時間戳快照。
- `data/context-factors.json`：每場最新觀測；前台Elo及因子卡片均有「陣容觀測已接入 · 尚未加權」。
- `data/context-pregame-ledger.json`：首次前瞻觀測與後續標籤；不與原整數預測封存混算。
- 關於平台列出覆蓋與限制；預測成績說明原模型歷史結果不代表陣容效果。

## 驗證與啟用限制

95項離線測試通過，包括新增的時序排除、傷停過期／空列表／存疑、缺角色資料、重複與衝突狀態、球員ID衝突、延長賽校正、快取原始時間、比分更正失效、有界請求與失敗快取、首次封存不覆寫及賽果匹配。JavaScript語法檢查通過。

目前沒有涵蓋歷史訓練與外測年份的當時陣容公告，因此新增預測效果仍不能可靠回測。下一階段需累積或合法取得有日期的歷史可用性、輪替及技術資料，逐項做時序外測、去除條件比較與機率校準。只有通過驗證才應啟用預測權重；本次沒有設自動啟用或憑人為印象調整勝率的捷徑。
