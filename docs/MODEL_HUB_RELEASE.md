# 可用模型整合、獨立盤口封存與即時結算

本次將現有公開CPU組件接入一套模型中心：Elo共同比分基準、整數因子、LightGBM樹模型。Elo維持主模型；新增融合仍為研究候選，不自動升級或連接真實下注。既有手機品牌開場與四個主導覽保留。

## 哪些已經可以整合

| 組件 | 狀態 | 是否可進入融合選權重 |
|---|---|---|
| Elo共同比分基準 | 有可重播歷史特徵與即時輸出 | 是 |
| 整數因子 | 有歷史規格與逐場輸出 | 是 |
| CPU樹模型 | 有原生模型、校準及快取 | 是，驗證可將權重選為0 |
| APEX v2.1 | 私人端最新核對有效預測0場 | 否 |
| 增量模型 | 私人端已學習46場，門檻100場 | 否 |

私人狀態為2026-11-02 09:36（台北）的授權彙總快照，不是即時私人資料橋接。沒有複製私人APEX程式、參數、SQLite或API金鑰到公開站。未具備有效輸出的組件不以其他模型的數字冒充；達到樣本門檻也不代表自動取得發布資格。

## 融合如何驗證

`model_hub.py` 使用共同時序特徵，按勝負、分差、總分分別處理。這三個組件共享歷史資料，不能當成三份獨立投票。融合內比分採既有候選研究的共同Elo比分基準；與舊公開Elo比分卡片的規格不可混算。

1. 原生樹模型訓練與選規格使用更早資料；整數權重只在較早訓練季擬合。
2. A期選因子的修正幅度，校準各組件勝率與比分誤差；B期晚於A期，選非負、合計1的分項權重。A、B不得共享台北比賽日，各期至少100場。
3. 權重以0.25為格距，保留至少25%共同Elo基準，附小型偏離懲罰。沒有預設三等分，也沒有要求所有組件都有非零權重。
4. 勝負使用機率線性池；分差和總分使用校準誤差分布的混合CDF，包含整數走盤。90%區間是結果參考區間，不是平均值信賴區間。三個目標獨立融合，沒有宣稱聯合比分分布。
5. 每週原生模型更新後，從該版真正排除於訓練的校準區段再分A/B建立當前融合。其他執行沿用內容雜湊快取。舊資料與程式更正可觸發重建，並保留版本。

歷史開發採2025前段校準、後段選權重，2026測試1,316場；2026曾用於更早研究，因此不是全新外部驗證。

| 開發測試指標 | 融合候選 | 同條件校準基準 |
|---|---:|---:|
| 勝負相符 | 884/1,316 | 887/1,316 |
| Brier（越低越好） | 0.21026 | 0.21084 |
| 分差MAE | 11.642 | 11.720 |
| 總分MAE | 15.404 | 15.551 |

比賽日成組重抽樣的改善95%區間：Brier −0.00033至+0.00141，分差MAE +0.032至+0.121分，總分MAE +0.046至+0.252分。勝率誤差區間跨零，方向相符數也未較佳，故維持候選。歷史參數與當前週參數可能不同；不能把歷史小幅比分改善當作已發布的過盤勝率。

目前本地實測的當前分項權重為Elo 25%、因子75%、樹模型0%。這是較早A/B資料選出的結果，不是依最近36場直接調整，也不代表樹模型永久無用。以正式排程產出的`model-hub.json`版本為準。

## 修正缺盤口就永遠缺成績的問題

舊流程只在首次發布勝負時記一次盤口；若當時缺報價，後續即使取得也無法累積該市場成績。本次新增`market-pregame-ledger.json`：

- 勝負仍保留首次發布；讓分與大小分各自於開賽前1至24小時、首次有有效新報價時封存當下的模型預測。
- 每模型家族、每賽事、每市場只收一次，跨模型版本不覆寫，不挑選後來較有利的盤口。
- 同event、日期、主客隊、報價擷取時間均需符合；報價不得在未來，也不得超過六小時。四分之一盤不支援。
- 舊紀錄只匯入當時已發布且本來有有效盤口的預測，不把今天的盤口補到已完賽或缺盤口的歷史場次。
- 手機成績頁分別顯示勝負、讓分、大小分封存時間。日期和市場篩選有效，缺盤不算輸或贏，走盤另列。
- 整數因子新賽事亦限制在1至24小時內首次封存，保留已公開的舊紀錄與版本，不刪除那些較早發布的預測。

## 比分與成績不再分開停住

`collect_scoreboard.py` 保留ESPN事件ID、主客隊、開賽時間；NBA來源則以唯一日期／對戰組合對接，並保留來源ID。舊版只有隊名、沒有日期的快照不自動合併，避免誤接重複對戰。

`result_ledger.py` 使用新鮮已確認終場比分更新賽程並結算Elo、因子、樹模型、融合及獨立盤口紀錄，不呼叫LightGBM訓練或語言模型。更正比分時保留舊結算修訂紀錄；賽前預測不修改。新增Elo自動封存從本次發布開始，舊公開核對檔仍可選歷史日期查看，不重算補填缺失的賽前預測。

快速比分工作流在主要比賽時段每15分鐘排程，其餘時段每小時；GitHub排程屬盡力執行，不保證準點。比分與完整模型收集採同一佇列，從最新main開始，使用獨立發佈worktree，避免舊任務覆蓋新封存。快速更新後會請求Pages部署。頁面分開標示比分時間、結算時間與完整模型資料時間，來源過期會提示。
